# v1.2.0：雙模式（本機 / 雲端）與 local-first 資料層

## 一句話

**App 有兩種模式；不論哪一種，會議資料都只存在這台裝置。**

```
App 啟動
  ├─ 本機模式（免登入）
  │    ASR  : whisper.cpp / WhisperKit + Breeze-ASR-26（CoreML encoder → ANE）
  │    摘要 : MLX Swift + Bonsai 27B 1-bit（約 3.9 GB）
  │    資料 : 裝置（IndexedDB；未來可換原生 SQLite）
  │
  └─ 雲端模式（Google 或帳密登入）
       Cloudflare Worker 固定入口 → 自動發現 Colab 網址
       → Colab 後端（27B + 4 語 ASR）→ 結果寫回裝置
```

Colab 只是「算力」。重啟、換 tunnel、沒網路都不會弄丟會議紀錄。

## P0 資料層（已完成）

`frontend/store.js`，IndexedDB 為主、localStorage 後備：

| store | 內容 |
|---|---|
| `kv` | 模式、個人檔案、設定 |
| `meetings` | 會議基本資料（名稱、日期、模式、狀態） |
| `transcripts` | 逐字稿（以 meeting_id 為鍵） |
| `summaries` | 會議重點 |
| `glossary` | 專有名詞 |
| `models` | 本機模型下載紀錄 |

寫入時機：

- 雲端上傳成功 → 建立 meeting
- 讀到逐字稿 / 重點 → 自動快取
- 本機 ASR 完成 → 寫入逐字稿
- 本機摘要完成 → 寫入重點
- 詞庫載入 / 新增 → 同步到裝置

讀取時機（避免失憶）：

- 開啟舊會議時後端連不上 → 自動改讀裝置副本
- 讀取重點失敗 → 讀裝置副本

匯出／還原：`Store.exportAll()` / `Store.importAll(data)`（之後可接「備份到檔案」按鈕）。

> 注意：PlayCover **重裝** App 會清掉 WKWebView 的 IndexedDB。
> 若要徹底防止，下一步是把 `store.js` 換成原生 SQLite（介面已預留）。

## P1 本機 ASR（Breeze-ASR-26）

- 外掛：`meetsum-local-asr`
- 引擎：`whisperkit`（一般 Whisper）或 `breezeasr`（Breeze-ASR-26）
- 模型不打包進 IPA，首次使用才下載
- Breeze 的社群釋出格式是 whisper.cpp（GGML + CoreML encoder），
  使用前需轉成 **WhisperKit CoreML 格式**：

```bash
# 1. 安裝轉換工具（macOS）
pip install "torch==2.5.0" "transformers==4.53" "numpy<2.4.0" coremltools huggingface_hub
pip install -e git+https://github.com/argmaxinc/WhisperKitTools.git

# 2. 轉換（Breeze-ASR-26 是 Whisper large-v3 的微調版）
#    --generate-quantized-variants 一定要搭配 --allowed-nbits
python scripts/convert_breeze_asr_26.py \
  --output-dir ./breeze-asr-coreml \
  --quantize 4bit

# 3. 驗證並發佈到自己的 Hugging Face repo（選用）
python scripts/convert_breeze_asr_26.py --verify-only \
  --output-dir ./breeze-asr-coreml \
  --hf-repo 你的帳號/breeze-asr-26-whisperkit \
  --hf-token "$HF_TOKEN"
```

> 輸出資料夾名稱會帶模型大小，例如
> `breeze-asr-coreml/MediaTek-Research_Breeze-ASR-26_632MB/`。
> 上傳時每個 variant 會變成 repo 的子資料夾，WhisperKit 就是用資料夾名稱找人。

GitHub Actions 也有現成 workflow：`.github/workflows/convert-breeze-asr-26.yml`。

### 模型要放哪裡

App 讀取 `Documents/WhisperKitModels/breeze-asr-26-coreml_4bit/`。
兩種方式：

1. **手動放入**（Mac / PlayCover 最簡單）
   `UIFileSharingEnabled` 已開啟，可從 Finder → App 文件 放入整個資料夾。
2. **從 Hugging Face 下載**
   在 `ios/App/App/Info.plist` 設定：

   ```xml
   <key>BreezeModelRepo</key>
   <string>你的帳號/breeze-asr-26-whisperkit</string>
   <key>BreezeModelVariant</key>
   <string>breeze-asr-26-4bit</string>
   ```

   再到 App 內「本機模型 → 下載」。

   `BreezeModelVariant` 可以留空：App 會向 Hugging Face 查詢 repo 內的資料夾，
   自動挑 MB 最小的量化版本（`whisperkit-generate-model` 產生的名稱帶有大小，
   例如 `MediaTek-Research_Breeze-ASR-26_632MB`，所以不要寫死）。

   GitHub Actions 的 `Convert Breeze-ASR-26 to WhisperKit Core ML` workflow
   轉換完成後會把每個 variant 上傳成 repo 的子資料夾，並印出要填的
   `BreezeModelRepo` / `BreezeModelVariant`。

沒有現成 CoreML 模型時，`scripts/convert_breeze_asr_26.py` 與上面的 workflow 就是「自行轉換」的路徑。

## P2 本機摘要（Bonsai 27B 1-bit / MLX）

- 外掛：`meetsum-local-llm`（新）
- 套件：`PrismML-Eng/mlx-swift-examples`（含 1-bit kernels）
- 模型：`prism-ml/Bonsai-27B-mlx-1bit`（約 3.9 GB），依裝置可降級 `Bonsai-8B-mlx-1bit`
- 流程：下載 → 載入 → 串流生成（`llmToken` 事件）→ 解析 JSON → 寫回裝置
- 提示詞要求模型輸出固定 JSON，前端 `normalizeLocalSummary()` 會補預設值
- 記憶體策略：ASR 跑完才載入 LLM；收到記憶體警告會自動卸載

> 1-bit 模型**必須**用 PrismML 的 mlx-swift fork；官方 mlx-swift 只能跑 4-bit。
> `Package.swift` 內已標註切換方式。

## P3 雲端模式：Google 登入 + 自動發現

### 1. Google OAuth（後端轉導式，不用原生 SDK）

| 端點 | 用途 |
|---|---|
| `GET /api/v1/auth/google/start` | 回傳 Google 授權網址 |
| `GET /api/v1/auth/google/callback` | 換 token、建立使用者、302 導回 `meetsum://auth?token=...` |

設定（`.env`）：

```env
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_BASE=https://你的後端網址
APP_URL_SCHEME=meetsum
```

Google Cloud Console 的 OAuth 用戶端（Web application）需加入
`{GOOGLE_REDIRECT_BASE}/api/v1/auth/google/callback`。

App 端：`startGoogleLogin()` 用系統瀏覽器開啟授權頁；
`appUrlOpen` 攔截 `meetsum://auth` 後以 token 呼叫 `/auth/me` 完成登入。
`Info.plist` 已加入 URL scheme `meetsum`。

### 2. Cloudflare Worker 固定入口

`infra/discovery-worker/`：

- `GET /current` → 目前 Colab 網址
- `POST /update`（Bearer `PUSH_TOKEN`）→ Colab 啟動時寫入
- 部署步驟見 `infra/discovery-worker/README.md`

Colab 端：`run_all.py` 在 tunnel 確認可用後會自動呼叫 `publish_discovery(PUBLIC_URL)`。

App 端：建置時帶入

```bash
VITE_DISCOVERY_URL=https://discover.你的網域/current npm run build
```

啟動時若使用者沒手動設定伺服器，會向 Worker 查目前網址（有快取與重試）。
手動設定的位址永遠優先。

## 已知限制

1. **Xcode**：開發機器目前 Xcode 損壞，Swift 只能靜態撰寫，需在 CI 或另一台 Mac 編譯驗證。
2. **1-bit MLX**：需 PrismML fork；若 fork 分支改名，請同步 `meetsum-local-llm/Package.swift`。
3. **Breeze 模型格式**：需先轉換成 WhisperKit CoreML；repo 未設定時 App 會給明確指示。
4. **PlayCover 重裝**：會清 IndexedDB；重要資料請先匯出，或改用原生 SQLite。
5. **免費簽名**：Personal Team IPA 7 天到期、僅限已註冊裝置；對外「下載即用」仍需 $99/年 + TestFlight。
